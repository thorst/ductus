# People, audit, alerts, owners

Read before changing: users and test accounts, the audit log, alerts, owners. Each note is something that already cost a debugging session; add a new one here (not in CLAUDE.md) when you solve something the next person would rediscover.

- **People (0.5.8.1):** `ductus user create|list|set|password|disable|enable|unlock` works on the database directly (`--password-stdin` for scripts; a terminal asks twice, no echo). Tests and demos that read a payload through the API need a token with `--permission payloads` (admins have every permission). Test users are named `test-user-...` (the store's last-admin test deletes such admins first, so a demo that makes an admin must name it that way). **Every test and demo deletes the accounts it makes** (accounts are never deleted in the product, so a long-lived dev database piled up 386 in a week and the Users page, which renders every account, timed out demo-ui's axe test): Rust tests name them with `ductus_store::testing::TestUsers` (feature `testing`, dev-dependencies only, never in the binary) and an async test ends with `people.forget().await` (its `Drop` is the fallback on failure, with a `lock_timeout`: blocking the test's runtime in `Drop` hung once, because a refused change's ROLLBACK is sent from that runtime and its locks stay until then); scripts call `forget_test_users PATTERN...` (`scripts/dev/db.sh`) in their `trap`; accounts the Playwright specs make start with `DUCTUS_PEOPLE_PREFIX` (demo-ui's `test-user-ui-<pid>-`), which demo-ui's trap deletes (there's no API to delete one). Both helpers clear sessions, tokens, settings and `message_actions.user_id/token_id` first and refuse any name not `test-user-*`; audit rows stay. A new API operation needs a row in `ACCESS` (`api/mod.rs` tests). The store test for the last admin only checks the guard when the test database has no other admin.
- **Audit (0.5.8.2):** a change that has a transaction takes an `&Audit` (`ductus_store::{Audit, By}`) and writes its row in it (`audit::insert`); one without writes the row first with `record_first` (API) or `Store::record`. New audit actions go in `docs/schema.md` (`audit_log.action`) and in the UI's `ACTIONS` map (`ui/src/components/audit-table.tsx`). Store tests that aren't about the log pass `quiet()`. Test users are `test-user-*`; the CLI tests and `demo-ui.sh` read `/audit` as a token or person with the `audit` permission. `ductus audit export` reads the database directly. The hourly trim deletes anything older than 6 years: a test that needs old rows backdates its own and trims with its own `keep`.
- **Alerts (0.5.8.3):** ductus.yaml is parsed through `env::parse_yaml` (so `${...}` can't break it) and only `alerts:` is substituted, per environment (`Settings::alerts(&env)`); everything else in it is read as written. **lettre's pooled SMTP transport must be built inside a Tokio runtime** (`Alerts::new` spawns; a plain `#[test]` aborts with "no reactor running": use `#[tokio::test]`). `chrono` has the `serde` feature only through the runtime's dependency tree: `cargo check -p ductus-runtime` compiled a `json!` with a `DateTime` in `ductus-store` that `cargo test -p ductus-store` alone refused; put times in JSON as `to_rfc3339()`. Store tests that make alerts delete them (`forget_alert`): an open test alert would show in a demo engine's counts (the API lists only the engine's own interfaces' alerts anyway). Demos that need mail or a webhook use `ductus sink --smtp`/`--http` (`--dir` keeps each one as a file).
- **Owners (0.5.8.6):** `ductus_core::owners::find` is the one rule for "which account does this owner text name" (alerts, `/owners`, `ductus owners`): add any new use there, don't match names again. **Since 0.6.7.2 it also reads former names**: build people with `ductus_runtime::alerts::people(&accounts.users, &accounts.former)` from `Store::accounts()` (not `users()`), or renamed owners read as nobody; pass `&[]` only where former names can't matter (the people picker). `Found::person()` is the account reached (One, Renamed, Reused); `owners::advice` words the ⚠ (renamed, reused, not an email) and `owners::fix` the command (`owners::shell` quotes). `owned` takes the resources too. `ductus owners` reads accounts only when `DUCTUS_DATABASE_URL` is set, and check.sh sets it: CLI tests of the plain report use `without_a_database`. The v0.5 demo (`demo-v05.sh`) runs its browser story with its own config (`ui/playwright.story.config.ts`, tests in `ui/story/`, not picked up by `demo-ui.sh`); the story starts and stops the lab's receiver itself (`ductus sink --reject TEXT` answers AR). It deletes its directory accounts with their `message_actions` at the end: `demo-ui.sh` deletes the same directory people at its start, and a `message_actions` row would refuse that (`users` is referenced). An `<input list=...>` (a datalist) has the role `combobox`, not `textbox`. In YAML, DNs in a `[flow, list]` split at their commas (`auth.ldap` now refuses a one-part group DN).
