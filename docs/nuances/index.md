# Nuances: what to know before you rely on it

Every engine has behaviour that surprises people the first time. Ductus can't remove all of it, but it can tell you about it up front. These pages are the running list: what happens, why, and how to write your interfaces and set expectations with it in mind.

Each entry has a **level** (1 = everyone needs it on day one, 5 = expert). The levels match the planned course tracks, from first interface to expert.

**For engine developers:** whenever a change adds or reveals a nuance, add it to its section's page in the same commit, with a level, and link it from the guide page it affects (`every_nuance_is_linked_from_a_guide` fails otherwise).

| Level | Who it's for |
|---|---|
| 1 Foundations | Writing a first interface |
| 2 Practitioner | Building and testing interfaces day to day |
| 3 Professional | Databases, APIs, files, schedules, ordering, retries |
| 4 Advanced | Isolation, performance, operations |
| 5 Expert | Delivery guarantees and failure semantics under crashes and runaways |
